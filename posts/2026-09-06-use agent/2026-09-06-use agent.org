** 开发过程中的小经验

记录一下 codex 开发记录，近几个月，使用大模型 vibe coding 多个项目，开发代码几十万，整体符合开发大型项目的规范，有有效测试，有架构设计以及分层，目录规范齐整，代码风格统一；整体给我的感觉是，是个不错的小帮手，偶尔还会有那么一两个出彩的亮点；最让人感觉特别好的是，查询各种资料来完善需求，完善交互，晚上设计；这些是非常耗费时间的，有需要大批量去整理资料的事情，分分钟钟搞定；是个非常不错的整理内容的好帮手；

deepseek、glm 等在代码项目开始的时候，比较好的一个特点是目录规范、结构弄得比较清晰；当然有有效的提示词约束 codex 应该也能弄得比较好，但我说的默认情况下；

另外显然在需求复杂到一定程度的时候牛逼厉害的模型自然能力出众很多，不啰嗦的利索能得出 ~跟你想法类似的答案来~ ，当然你说这个答案是否正确全靠你自己的认知；

同时，模型可能给了你解决方案，但不一定把解决方案实现完备，最好保存好这个解决方案，反复去问几次是否已经实现完备，这会使得跟预期偏差会少一些，是个不错的实现经验；

强类型的语言显然更有利于静态检查，所以一般会使验证这个事情更简单一些，那么就意味着开发过程中验证这个事情完全可以交给模型去做，且准确性比较高；但有一个非常需要关注的点在于：验证程序时间不太过长，不然影响效率，人可能无法等这么久；

得防止代码信息密度爆炸，不能最后不可控，不然模型再牛逼也改不动，改不动人又看不懂的时候自然就是灾难的开始；

agent 等会欺骗自己来得到正确的结果，比如你要求是 a、b、c 但一般可能人类程序员会考虑 c、d、e，但模型不会，所有门槛需求需要全面，不然可能会欺骗以完成 a、b、c，而 c、d、e 到时候可能就成为 ~爆炸~ 的口子；

gui 类型的程序，基本都能做得比较好了，但前提是你能用语言去描述你想要什么样子的交互以及效果，同时也要防止抽象过度以及毫无抽象使得状态发生不可控制的可能；

以上，大概就是我在过程中的一些小感受，也没有详细举例子说明，我就记录一下这些情况；


** 开发有趣的项目

第一个我先为了熟悉 Agent 架构而开发了 morph 这样一个 agent 方案，现在我在各种场景下都集成了 morph，可以驱动 Mobile App 成为这些 Agent 产品的底层架构，同样也能成为 vim、emacs 这样的编辑器的伴侣 agent，集成特别方便且简单；

第二个项目主要是给自己打造了一个写文字和写代码的编辑器，很多人说为啥还要搞一个编辑器，其实很简单，只是想让自己的 ~刀~ 更锋利一些，比如这篇文章就是用这个编辑器开发的；编辑器支持 lua 写插件，我插件集成了 org、org roam 以及 markdown，非常好用。我后续的知识管理、博客站点等都可以使用这个编辑器搞定，我感觉是个非常不错的实现；

第三个项目我还没有开始做，但迟早我会去做下去，就是开发一个 Linux 桌面环境，熟悉整个操作系统的制作过程，相当于我从 DWM 做一个升级操作吧，以前都是 DWM 打造的解决方案，后续可能就直接自己设计一个出来，借助 ~codex~ 强大的模型以及收集处理信息的能力；当然，其实开发代码用 morph 也还是能行的，但确实如果达到 ~codex~ 这样的智能程度，我可能还得花很长时间进行优化，当然这个也是我正在做的；

接下来，把所有学到的东西往业务场景去融合，看是否能提升一下业务的上限效率，以及能否给业务以一些想法最终去落地；
