* Introduction

This is the source for my website. It is written in [[https://orgmode.org][Org mode]]
and exported by **mvi**.

Each published Org file has a unique basename. The build exports every document
as standalone HTML with mvi's bundled pure-Lua Org renderer, and generates the
homepage article list from the files below =posts/=. No Emacs, weblorg or Jinja
templates are required.

Build locally with:

#+begin_src sh
make
#+end_src

The generated site is written to =public/=. Old URLs fall through to
=404.html= and redirect to the homepage.

Build and preview it locally at =http://127.0.0.1:8000=:

#+begin_src sh
make preview
make preview PORT=8080  # optional custom port
#+end_src

The homepage preview uses a stable grayscale image from Lorem Picsum. A release
downloads a new 900×1200 WebP image, stores it in =public/assets/home/=, and
publishes that file with the site. Visitors never load it from Picsum directly.

** Images

Put images in an =images/= directory next to the Org document:

#+begin_example
posts/2026-08-26-example/
├── 2026-08-26-example.org
└── images/
    └── screenshot.png
#+end_example

Reference them with a relative Org link:

#+begin_src org
[[file:images/screenshot.png]]
#+end_src

The build copies them to =public/assets/2026-08-26-example/= and rewrites the
generated HTML automatically. Each page has its own asset directory, so image
filenames may be reused safely across posts.

Publish the generated site to the =gh-pages= branch after reviewing it:

#+begin_src sh
make release
#+end_src

The release runs in a disposable repository, creates a commit containing only
=public/=, and pushes that commit to =origin/gh-pages=. It does not switch or
commit the source branch.
